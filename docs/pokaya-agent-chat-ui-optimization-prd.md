# Pokaya Agent Chat UI Optimization PRD

## 1. 背景

当前 Agent 聊天区已经从黑色卡片改成浅色卡片，但部分文字和状态组件仍沿用旧深色主题的低对比样式。截图中出现三个问题：

1. Agent 回复正文上半部分过淡，用户需要费力阅读。
2. 运行状态卡「已完成 / 理解需求 / 回复建议 / CHAT」几乎不可见。
3. 回复内容、建议列表、状态卡混在同一视觉层级里，用户不知道重点是“Agent 说了什么”还是“系统状态是什么”。

这会让用户觉得 Agent 不可靠、界面像 debug 页面，并降低用户继续输入指令的意愿。

## 2. 目标

把 Agent 聊天区优化成「用户先看得懂回复，再看得到执行状态」的浅色对话体验。

核心目标：

- 提升 Agent 消息正文可读性。
- 弱化内部状态感，强化用户能理解的进度表达。
- 保留必要执行透明度，但不让 debug 信息抢主视觉。
- 所有文字在桌面和移动端都达到清晰可读。

## 3. 非目标

- 不改 Agent 后端工具逻辑。
- 不改扣 credit 确认逻辑。
- 不新增复杂 Markdown 编辑器。
- 不把 Agent 做成客服机器人头像系统，本期只优化当前卡片式体验。

## 4. 用户问题

### P0：状态卡文字不可读

截图底部的「已完成」「理解需求」「回复建议」接近白色，背景也是浅色，用户几乎看不到。

原因推测：

- `.agent-run-card` 或其子元素仍使用深色主题下的 `#fff` / 低透明白色。
- 浅色 Agent 卡片没有覆盖所有嵌套组件的颜色。

### P0：Agent 正文对比度不足

顶部问候、workspace 概览、结尾提示文字太淡。用户只能看清粗体列表，普通正文读起来像 disabled 状态。

### P1：信息层级混乱

当前同一张卡里有：

- Agent 标签
- 正文
- 建议列表
- 运行状态卡
- 状态标签 CHAT

用户第一眼不知道哪个是主要回复，哪个是系统状态。

### P1：状态卡过大但价值低

Agent Run Card 占据大量空间，但展示的信息只是「已完成 / 理解需求 / 回复建议」。这对用户价值有限，更适合折叠或压缩。

## 5. 设计原则

1. **正文优先**：用户打开 Agent 后，第一眼应该读到 Agent 的答案。
2. **状态辅助**：执行状态只做轻量提示，不压过正文。
3. **浅色一致**：所有 Agent 内部组件都必须适配浅色背景。
4. **少 debug 感**：避免 CHAT、intent、confidence 这类内部词直接露给普通用户。
5. **可扫读**：列表、重点词、状态都要能快速扫一眼理解。

## 6. 功能需求

### 6.1 Agent 消息正文样式

要求：

- 正文颜色使用深紫黑：`rgba(31, 6, 38, 0.92+)`
- 普通正文不低于 `15.5px`
- 行高 `1.55-1.65`
- 普通正文 weight 不低于 `650`
- 重要文字 strong 使用更深紫色：如 `#4f055f`
- 非重点说明文字也不能低于 `rgba(31, 6, 38, 0.72)`

验收：

- 截图中「你好！欢迎使用...」「目前你的 workspace...」「直接告诉我就好！」肉眼清晰可读。

### 6.2 Agent Run Card 浅色适配

要求：

- `.agent-run-card` 改成浅色状态条，而不是大面积白字状态面板。
- 背景建议：`#fffaf2` 或 `rgba(244, 202, 50, 0.08)`
- 边框建议：`rgba(93, 8, 108, 0.10)`
- 主状态文字使用深色：`rgba(31, 6, 38, 0.88)`
- 步骤文字使用深色：`rgba(31, 6, 38, 0.78)`
- 完成圆点保留绿色，但不要只有圆点没有文字对比。

验收：

- 「已完成」「理解需求」「回复建议」清楚可见。
- 不再出现白字消失在浅色背景里的情况。

### 6.3 隐藏内部标签

要求：

- 普通用户不要看到 `CHAT` 这种内部 intent 标签。
- 可改成人话标签：
  - `CHAT` -> `回复`
  - `generate` -> `生成任务`
  - `schedule` -> `排期任务`
  - `publish` -> `发布确认`
- 或本期直接隐藏 intent 标签。

验收：

- 截图右下角不再出现突兀的 `CHAT`。

### 6.4 状态卡压缩

要求：

- completed 状态下，状态卡高度应明显压缩。
- 建议显示为一行：
  - `已完成 · 已理解需求 · 已回复建议`
- running / waiting_confirmation 状态才展开步骤。

验收：

- 普通已完成回复不会占用大片底部空间。
- 等待确认时仍显示确认卡。

### 6.5 Agent 首条欢迎回复优化

当前欢迎回复内容合理，但视觉上太长。建议改成更短、更像入口：

推荐文案：

```text
你好，我是 Pokaya Agent。

当前 workspace：
- 83 credits
- 当前项目：赌博
- 已有 1 个生成结果，3 个排期帖子

你可以直接让我：
- 生成图片/视频
- 做 7 天内容计划
- 检查今天缺什么
- 创建排期草稿
```

要求：

- 避免过多粗体。
- 避免一句话里混太多信息。
- 项目名可用 pill 显示，但 pill 不要影响阅读。

## 7. 交互需求

### 7.1 完成态

显示：

- Agent 回复正文
- 底部轻量状态：`已完成 · 已回复`

不显示：

- intent 英文标签
- 置信度
- 大块 debug 状态卡

### 7.2 等待确认态

显示：

- Agent 说明为什么需要确认
- 扣费/发布影响
- Confirm / Cancel

要求：

- 扣 credit 的确认卡必须突出 credits。
- Confirm 按钮文案改为：`确认并扣 credits`
- Cancel 文案：`取消`

### 7.3 追问态

当 Agent 不确定时：

- 不显示“失败”
- 不显示复杂 run card
- 显示轻量提示：`需要你补充一下`

## 8. CSS 实施范围

重点检查这些 selector：

- `.agent-page-panel .agent-message`
- `.agent-page-panel .agent-thread article.assistant`
- `.agent-run-card`
- `.agent-run-head`
- `.agent-run-steps`
- `.agent-run-steps li`
- `.agent-run-steps span`
- `.agent-run-steps small`
- `.agent-confirm-card`

需要确保所有这些在浅色背景下有明确 color override。

## 9. 验收标准

### 桌面端

- 1440px 宽度下，Agent 回复普通正文清晰可读。
- 已完成状态卡不再出现白字。
- Agent 回复卡高度合理，不出现大片空白。
- 用户能在 3 秒内理解 Agent 当前回复和下一步建议。

### 移动端

- 390px 宽度下，列表不溢出。
- 状态卡不横向撑破。
- Confirm / Cancel 按钮可点击区域足够。

### 技术验收

- `npm run build` 通过。
- 无新增外部依赖。
- 不影响 Agent confirmation / credit deduct 后端逻辑。
- 不提交无关截图、测试产物、历史草稿文件。

## 10. 优先级

P0：

- 修复 Agent Run Card 白字不可读。
- 加深 Agent 普通正文。
- 隐藏或翻译 `CHAT` 标签。

P1：

- completed 状态压缩为一行。
- 等待确认卡强化扣费信息。
- 优化欢迎回复文案。

P2：

- 增加 hover/展开详情，仅给高级用户查看执行步骤。
- 根据 running / completed / waiting_confirmation 使用不同视觉状态。
