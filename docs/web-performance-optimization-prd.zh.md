# Pokaya 全站网页性能优化 PRD

## 1. 背景

当前 Pokaya 网页整体体验有明显卡顿感，尤其可能出现在首页、Studio 工作台、Agent 页面、图片/视频结果墙、Admin CRM、内容库和包含 3D Agent 的页面。卡顿不是单一 UI 问题，而是由渲染架构、资源体积、动画策略、事件绑定、CSS 规模和媒体加载共同造成。

本 PRD 目标是把 Pokaya 从“功能能用但交互沉重”的状态，优化成“打开快、切页快、输入不卡、滚动稳、生成过程反馈顺”的 AI 内容生产工作台。

## 2. 当前技术观察

基于当前代码初步扫描：

- `src/main.js` 约 591KB，承担首页、Studio、Agent、Admin、生成器、结果墙等大量页面逻辑。
- `src/styles.css` 约 727KB，样式集中度高，长期叠加后容易造成选择器匹配和样式计算负担。
- `src/agent3d.js` 使用 Three.js 和 GLB 模型，`public/models/agent/pokaya-agent.glb` 约 996KB，并持续 `requestAnimationFrame` 渲染。
- 主渲染函数使用 `app.innerHTML = ...` 整页重绘；状态更新后会重新执行 `bind()`，为大量 DOM 节点重复查询并绑定事件。
- 页面中存在大量图片、视频、QA 截图、演示视频、品牌图、结果媒体和动态卡片，若加载策略不精细，会拖慢首屏和滚动。
- 搜索、筛选、输入框、Agent 消息更新、结果标题编辑等交互中，部分状态变化会触发较大范围重绘。

这些观察说明：当前卡顿优先不是“某个按钮慢”，而是全站前端运行时成本偏高，需要按阶段治理。

## 2.1 最新线上状态

截至提交 `84918b1 Improve sidebar navigation responsiveness`，项目已经完成一轮 sidebar 和图片墙的体感优化，并已推到 `origin/main`。

已完成内容：

- 点击当前页面 / 当前项目 / 当前 step 时，跳过无意义整页重渲染。
- sidebar 切页改为延后一帧执行，让浏览器先绘制点击反馈，再执行重页面切换。
- 图片墙首屏高优先级加载从 12 张降到 6 张。
- 非全屏图片解码从同步倾向改为 `decoding="async"`，减少大图解码阻塞主线程。
- sidebar、sidebar scroll area、图片墙卡片增加 `contain` / `content-visibility`，降低 hover、active、offscreen card 对整页 repaint 的牵连。

当前判断：

- 这轮优化属于正确的 Phase 1 止血，能缓解 sidebar 点击卡死和图片墙首屏压力。
- 这轮优化不是根治，因为 `render()` 整页 `innerHTML` 重建、`bind()` 大量重新绑定事件、图片墙未虚拟化、媒体仍使用原图进入页面等核心问题仍存在。
- 新增的 `content-visibility: auto` 需要补稳定占位；否则图片墙卡片在进入视口或图片比例回填时，仍可能造成“闪缩 / 跳动”。

下一步优先级：

1. 专门处理闪缩：稳定卡片占位、固定 media ratio、补 `contain-intrinsic-size`、避免图片 `onload` 后大幅改布局。
2. 处理图片墙根因：缩略图代理、虚拟列表、视频 poster-first。
3. 处理渲染根因：事件委托、局部渲染、Agent 消息增量更新。

## 2.2 本轮执行状态

已开始执行 PRD 的 Phase 1 闪缩止血，首轮改动聚焦图片墙稳定性：

- 图片墙结果卡输出稳定的初始 `data-media-ratio` 和 `--media-ratio`。
- 使用 `content-visibility: auto` 的图片墙卡片补 `contain-intrinsic-size`，避免离屏卡片没有稳定占位。
- 图片 / 视频加载完成后，只允许小幅修正卡片比例；比例差距过大时保持初始布局，避免卡片突然变宽或变高。
- 全局 `html` 增加 `scrollbar-gutter: stable`，降低页面内容长度变化或弹窗开关时的横向抖动。

本轮仍未覆盖：

- 图片墙虚拟列表。
- 后端缩略图代理。
- 全局事件委托。
- `render()` 局部化重构。

## 2.3 第二轮执行状态

已继续执行卡顿优化，重点从“闪缩止血”推进到“减少 DOM、媒体和事件绑定压力”：

- 图片墙改为窗口化批量渲染：默认先渲染 48 个结果，每次点击 `Load more` 再追加 48 个，避免 100+ 素材一次性创建全部 DOM 和媒体请求。
- 图片墙视频卡片改为 poster-first：墙面不再创建真实 `<video src>`，只显示轻量视频占位；点开预览时才加载视频。
- 常用点击行为接入根节点事件委托：sidebar page / step / project、结果预览、结果操作、图片模型选择、取消生成、图片墙加载更多不再每次 render 后逐节点绑定。
- Admin 搜索改为短 debounce，避免每输入一个字符就立即整页重绘。

仍需后续深水区：

- 真缩略图代理：需要引入图片处理依赖、CDN image variant，或在生成入库时保存缩略图；单靠当前 Express 原样代理无法真正缩小图片字节。
- 更完整的列表虚拟化：当前是批量窗口化，不是滚动虚拟列表。
- 局部渲染：`render()` 仍会替换整个 `#app`。
- 路由级拆包：当前首页仍会随主 bundle 带入较多 Studio 逻辑。

## 3. 用户问题

### 3.1 首页

用户打开首页时，可能感觉：

- 首屏出现慢，图片和视觉层加载不够稳。
- 滚动时动效、阴影、渐变和媒体导致掉帧。
- 移动端首屏资源压力更明显。

### 3.2 Studio 工作台

用户进入 Studio 后，可能感觉：

- 页面切换、tab 切换、项目切换有延迟。
- 输入 prompt、编辑字段、切换筛选时 UI 反应不够即时。
- 结果墙图片/视频多时滚动卡顿。
- 侧边栏、主内容、浮动控件一起重绘，操作成本被放大。
- 页面偶尔“闪缩”：内容先变小、再恢复，或某个区块突然跳一下。

### 3.3 Agent 页面

用户使用 Agent 时，可能感觉：

- 打字、粘贴、消息流更新时有顿挫。
- 3D Agent 动画一直占用渲染资源。
- 长对话、多卡片、多附件时页面越来越慢。

### 3.4 Admin / Content Library

管理员或重度用户可能感觉：

- 列表筛选、搜索、用户切换、结果预览响应慢。
- 大量 DOM 一次性渲染，滚动和点击反馈不够轻。

### 3.5 页面闪缩 / 闪烁 / 跳动

用户反馈页面会“闪缩”，需要作为独立 P0 体验问题处理。这里的“闪缩”包括：

- 页面打开时先显示一个尺寸，随后整体缩放或宽度变化。
- 切换 tab、打开弹窗、生成结果插入时，页面闪一下。
- 图片、视频、3D canvas、logo 或结果卡先占 0 高度，加载后把布局撑开。
- 移动端地址栏收起 / 展开时，使用 `100vh` 的区域高度突变。
- 页面出现 / 消失滚动条时，内容宽度发生横向抖动。
- 字体、图标或品牌图片加载后，文字和按钮重新排版。
- Agent 流式回复、结果墙刷新、侧边栏折叠时，主内容被整页替换导致视觉闪烁。

闪缩的影响比普通慢加载更刺眼：用户会感觉页面“不稳”“像坏了”“刚点完就跳走”。因此本 PRD 将其和卡顿一起治理。

## 4. 产品目标

### 4.1 体验目标

- 首屏打开更快：用户能更早看到可读内容和主要 CTA。
- 交互更轻：输入、切 tab、开弹窗、切项目不明显卡顿。
- 滚动更稳：结果墙、内容库、Admin 列表、Agent 消息流滚动接近 60fps。
- 生成过程更顺：生成中状态、进度、取消、结果插入不造成整页跳动。
- 移动端可用：低端手机也能完成注册、进入 Studio、生成和查看结果。

### 4.2 技术目标

- 降低首屏 JS / CSS 阻塞成本。
- 减少整页重绘和重复事件绑定。
- 将重资源按页面、按视口、按用户意图懒加载。
- 为 3D、视频、动画建立暂停和降级机制。
- 建立可持续的性能预算和回归检查。

## 5. 非目标

- 本期不重做产品定位、价格、文案和视觉品牌。
- 不更换前端框架作为第一优先级；如果后续迁移到 React/Vue/Svelte，应作为独立工程 PRD。
- 不删除核心功能来换取性能，除非某些装饰性动画或重复展示被确认无业务价值。
- 不先改后端 AI 生成速度，本 PRD 聚焦网页体验卡顿。
- 不以本地高配机器体验作为唯一标准，必须覆盖真实用户设备。

## 7. 优化策略

## 7.1 第一阶段：性能止血

目标：不大改架构，先解决最明显的卡顿来源。

### 7.1.1 建立性能基线

执行内容：

- 使用 Lighthouse / WebPageTest / Chrome Performance 记录首页、Studio、Agent、Admin 的当前表现。
- 在本地和线上分别测量：首屏、切页、输入、滚动、弹窗、结果墙。
- 保存性能报告截图和 trace，作为后续对比基线。

交付物：

- `docs/performance-baseline-report.md`
- 每个核心页面至少一份 desktop 和 mobile 记录。

验收标准：

- 能明确列出 Top 10 性能瓶颈：脚本执行、样式计算、布局、图片、视频、WebGL、长任务等。

### 7.1.2 闪缩和布局跳动止血

执行内容：

- 为所有首屏图片、品牌 logo、mascot、结果卡图片、视频、canvas、3D 容器设置稳定 `width`、`height` 或 `aspect-ratio`。
- 为使用 `content-visibility: auto` 的图片墙卡片补 `contain-intrinsic-size`，确保离屏卡片有稳定占位。
- 图片墙卡片优先使用生成参数、结果类型或默认比例决定初始 `--media-ratio`，不要等图片 `onload` 后才第一次确定卡片比例。
- 如果必须在图片 `onload` 后修正比例，只允许小幅修正；超过阈值时保持旧布局，避免卡片突然变宽或变高。
- 避免首屏或 Studio 主容器使用会被移动端地址栏影响的裸 `100vh`；改用 `100dvh` / `min-height` fallback。
- 为页面根容器保留滚动条空间，例如使用 `scrollbar-gutter: stable`，避免弹窗或内容长度变化造成横向抖动。
- 弹窗打开时不要让 body 宽度变化；锁滚动时补偿 scrollbar 宽度。
- 字体、图标、logo 加载前保留占位，避免文字和按钮二次排版。
- 生成结果插入、Agent 消息追加、列表筛选时，不替换整页 shell，只更新局部区域。
- 关闭会触发布局变化的入场动画，例如从 `width/height/top/left` 动画改为 `transform/opacity`。
- 检查 `.loading`、空状态、skeleton 和真实内容之间的尺寸是否一致，避免从 loading 切到页面时整体缩放。

验收标准：

- 首页首屏加载时没有明显白闪、整体缩放或横向抖动。
- Studio 切换 step / page 时侧边栏和主框架保持稳定。
- 打开弹窗和关闭弹窗不改变页面宽度。
- 插入新结果卡时，只影响结果区域，不让整个工作台跳动。
- 移动端地址栏收起 / 展开时，主操作区不发生剧烈高度抽动。

### 7.1.3 媒体资源懒加载和压缩

执行内容：

- 首页非首屏图片统一 `loading="lazy"`、`decoding="async"`。
- 首屏关键图设置明确尺寸，避免布局抖动。
- 视频默认 `preload="metadata"` 或 `none`，非用户可见区域不预加载完整文件。
- 移动端优先使用小尺寸图片或静态 poster，避免直接加载大视频。
- 结果墙缩略图使用缩略版，不直接加载原图/原视频。

验收标准：

- 首页首屏网络请求数量下降。
- 非首屏媒体不在初始加载阶段抢带宽。
- 结果墙滚动时不出现大量同步图片解码造成的卡顿。

### 7.1.4 3D Agent 按需渲染

执行内容：

- 3D Agent 只在可见区域启动渲染。
- 页面不可见、浏览器后台、卡片离开视口时暂停 `requestAnimationFrame`。
- `prefers-reduced-motion`、低端设备、移动端低电量场景下默认降级为静态 mascot 或低帧率。
- GLB 模型改为用户进入 Agent / Studio 相关区域后再加载。

验收标准：

- 首页或非 Agent 页面不因 3D 模型持续占用 GPU。
- 切到后台 tab 后渲染停止。
- 低性能设备仍能使用核心表单和生成流程。

### 7.1.5 降低高成本 CSS 效果

执行内容：

- 审计大面积 `box-shadow`、`filter`、`backdrop-filter`、复杂渐变、持续动画。
- 对滚动容器、结果卡、侧边栏、浮动控制台减少过重阴影和滤镜。
- 将动画限制在 `transform` 和 `opacity`，避免频繁触发布局和绘制。
- 对页面区块增加 `content-visibility: auto` 和合理的 `contain`。

验收标准：

- 滚动 Performance trace 中 paint 和 style recalculation 时间下降。
- 视觉质感保留，但不以昂贵滤镜堆叠实现。

## 7.2 第二阶段：渲染架构优化

目标：减少整页重绘，让状态更新只影响必要区域。

### 7.2.1 拆分全局 render

当前问题：

- `render()` 会整页 `innerHTML` 替换，状态变化会重新创建大部分 DOM。
- `bind()` 每次渲染都查询大量选择器并绑定事件，页面越复杂成本越高。

执行内容：

- 将页面分成稳定 shell 和局部 view：
  - App Shell
  - Sidebar
  - Topbar / Project Header
  - Workspace View
  - Modal Root
  - Toast / Global Dock
- 对高频状态更新使用局部 patch：
  - Agent 输入框
  - Agent 消息追加
  - 搜索筛选
  - 结果标题编辑
  - 生成进度
  - 弹窗开关
- 已有 `updateModalRoot()` 可以作为局部渲染模式的第一步扩展。

验收标准：

- 输入 prompt 不触发整页重绘。
- 打开/关闭弹窗不重绘 Sidebar 和 Workspace。
- 切换筛选只更新列表区域。

### 7.2.2 事件委托替代重复绑定

当前问题：

- `bind()` 中对大量 `[data-*]` 节点逐个绑定事件。
- 每次重绘后都需要重新查询和绑定。

执行内容：

- 在 `app` 根节点建立统一事件委托：
  - `click`
  - `change`
  - `input`
  - `submit`
  - `keydown`
  - `paste`
- 保留少数必须逐节点绑定的复杂交互，例如 drag/drop、ResizeObserver、特定滚动监听。
- 对搜索输入、prompt 输入使用 debounce 或局部 state，不立即触发全局 render。

验收标准：

- 常规 click/change 不再需要全量 querySelectorAll。
- 一次 render 后的事件绑定耗时明显下降。
- 动态插入的新按钮天然可用。

### 7.2.3 列表和结果墙虚拟化

执行内容：

- 对结果墙、资产库、Admin 用户列表、Agent 历史会话、长消息流增加虚拟列表策略。
- 首屏只渲染可见项和少量 buffer。
- 滚动时复用 DOM 或按窗口切片渲染。
- 视频缩略图默认 poster，点击后才加载 video。

验收标准：

- 100 个结果以内页面仍然可滚动。
- DOM 节点数量受控。
- 列表筛选不会造成长时间白屏。

### 7.2.4 Agent 消息流增量更新

执行内容：

- 新消息追加时，只 append 新 message，不重绘整条 thread。
- 打字流式输出只更新当前 message 内容。
- Markdown 渲染加缓存，避免每次状态更新重复解析历史消息。
- 长消息折叠、工具卡片延迟渲染。

验收标准：

- Agent 长对话后输入仍顺。
- 流式回复不会导致整个 thread 抖动。
- 滚动位置保持稳定。

## 7.3 第三阶段：代码拆包和加载策略

目标：把“所有页面一次性下载和解析”改成“进入哪个页面加载哪个能力”。

### 7.3.1 路由级代码拆分

执行内容：

- 将首页、登录/注册、Studio Project、Agent、Admin、Billing、Autopost、SOP、Content Library 拆成动态模块。
- 首页首包不包含 Admin、Agent、3D、复杂生成器逻辑。
- Studio 默认只加载当前页面模块，用户切 tab 时再动态 import。

验收标准：

- 首页初始 JS 显著下降。
- 登录前用户不会下载 Studio 重逻辑。
- Admin 逻辑不会进入普通用户首包。

### 7.3.2 CSS 拆分

执行内容：

- 将 `styles.css` 拆为：
  - base tokens
  - public homepage
  - auth
  - studio shell
  - generator pages
  - agent
  - admin
  - modal/components
- 删除过期样式、重复样式和只用于旧版截图的样式。
- 建立 CSS 预算和未使用样式审计。

验收标准：

- 首页不加载完整 Studio CSS。
- Studio 页面样式计算成本下降。
- 样式文件更容易维护，不再靠不断追加覆盖解决问题。

### 7.3.3 第三方与图标优化

执行内容：

- 审计 Lucide 图标创建成本，避免每次 render 全局 `createIcons()` 扫描全页面。
- 只对新增区域初始化图标，或改为字符串 SVG / 图标组件缓存。
- Three.js 只在需要 3D 时动态 import。

验收标准：

- 常规状态更新不全页面重建图标。
- 首页不加载 Three.js。

## 8. 页面级优化方案

### 8.1 首页

优先级：

1. 降低首屏媒体体积。
2. 首屏关键文案先渲染，视觉资产渐进加载。
3. 非首屏 section 使用 `content-visibility`。
4. 动效遵守 reduced motion。
5. 首页不加载 Studio / Admin / Agent 逻辑。

验收：

- 移动端 4G 模拟下 3 秒内看到完整主文案和 CTA。
- 首屏滚动无明显掉帧。

### 8.2 Studio Project

优先级：

1. Project Shell 稳定，不因字段变化整页刷新。
2. Prompt 输入、模型选择、比例选择局部更新。
3. 结果墙缩略图懒加载和虚拟化。
4. 上传区和生成区的状态更新不影响侧边栏。

验收：

- 连续输入 prompt 无卡字。
- 切换 step 在 500ms 内稳定。
- 50 个结果滚动顺畅。

### 8.3 Agent

优先级：

1. 3D Agent 可暂停、可降级。
2. 消息流增量渲染。
3. Markdown 缓存。
4. 附件预览懒加载。
5. Agent 历史列表虚拟化。

验收：

- 50 条消息后输入仍顺。
- 流式回复时页面不整体闪烁。
- 3D 离屏暂停。

### 8.4 Admin CRM

优先级：

1. 用户列表分页或虚拟化。
2. 搜索和筛选 debounce。
3. 用户详情局部刷新。
4. 高成本图表和统计延迟加载。

验收：

- 搜索输入不阻塞。
- 切换用户详情不重绘整页。

### 8.5 Content Library / 结果资产

优先级：

1. 图片/视频缩略图分层加载。
2. 视频点击后才加载播放器。
3. 预览弹窗局部渲染。
4. 列表滚动虚拟化。

验收：

- 多媒体资产超过 100 个仍可用。
- 打开预览不影响列表滚动位置。

## 12. 风险与应对

### 12.1 局部渲染引入状态不一致

应对：

- 先从 modal、Agent message、result wall 这类边界清晰区域试点。
- 每个局部渲染函数都明确输入 state 和输出 DOM 范围。

### 12.2 过度懒加载导致用户看见空白

应对：

- 首屏关键内容不懒加载。
- 媒体使用 skeleton、poster、固定尺寸占位。

### 12.3 降低动效影响品牌质感

应对：

- 保留关键品牌动效，但减少持续 GPU 消耗。
- 在低端设备和 reduced motion 下自动降级，而不是全量移除。

### 12.4 拆包后路由切换出现加载等待

应对：

- 登录后预加载用户最可能进入的 Studio Project 模块。
- 鼠标 hover / tab 可见时预取下一页面模块。
- 模块加载期间显示轻量 skeleton。

## 13. 优先级建议

如果只做一轮，建议顺序如下：

1. 先测量首页、Studio、Agent 的真实卡顿点。
2. 暂停离屏 3D Agent，Three.js 按需加载。
3. 媒体资源懒加载、缩略图、视频 poster。
4. 将全局事件绑定改为事件委托。
5. Agent 消息和结果墙局部渲染。
6. 首页和 Studio 做路由级拆包。

这套顺序的原因是：前 3 项能最快改善感知体验，4-5 项解决高频交互卡顿，6 项解决长期包体和架构问题。
